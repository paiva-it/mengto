# mengto — web design skills gallery

Astro 7 + Tailwind 4 + React 19 islands. Local only.

- `/` — home: one card per skill (`src/pages/index.astro`), data from `src/data/skills.json`
  (generated by `node scripts/gen-manifest.mjs` from `.skills/*/SKILL.md`) merged with
  `src/data/meta/<name>.json` (written alongside each example page).
- `/skills/<name>/` — one example page per skill, built by following that skill.
- Card previews are `public/previews/<name>.jpg`, captured by `pnpm capture [names…]`
  against the running dev server. Hovering a card swaps in the live page in an iframe.
- `.skills/` holds the skill sources (gitignored; copied from `~/Downloads/web-design-skills`).

## Dev server

One shared server: `pnpm astro dev --background --port 4321` (`astro dev status|logs|stop`).
Several builders use it at once — never stop or restart it; start it only if it is down.

## Example page contract

Every skill page owns exactly these paths and nothing else:

| Path                                   | What                                                  |
| -------------------------------------- | ----------------------------------------------------- |
| `src/pages/skills/<name>.astro`        | the page (route `/skills/<name>/`)                    |
| `src/components/skills/<name>/**`      | optional: React islands, helpers, shaders             |
| `public/skills/<name>/**`              | optional: images, textures, models, video             |
| `src/data/meta/<name>.json`            | card metadata (shape below)                           |

Rules:

- **Never** edit `package.json`, the lockfile, `astro.config.mjs`, `src/styles/global.css`,
  `src/components/BackPill.astro`, scripts, or another skill's files. Never run `pnpm add/install`.
- Installed: `three`, `gsap` (incl. ScrollTrigger etc.), `lenis`, `cobe`, `globe.gl`, `matter-js`,
  `vanta`, `border-beam`, `metal-fx`, `thinking-orbs`, `shaders` (`shaders/react`),
  `iconify-icon`, `react`, `react-dom`, `tailwindcss`. Anything else: import from a pinned CDN
  ESM URL (`https://esm.sh/<pkg>@<ver>`) inside the page script, and say so in `notes`.
- The page is a full document in the `.astro` file: own `<html lang="en">`, `<head>` (charset,
  viewport, `<title>`), Google Fonts `<link>`s allowed. Include `<BackPill />` from
  `../../components/BackPill.astro`. Tailwind: `import '../../styles/global.css'` in frontmatter;
  scoped `<style>` is fine too.
- Vanilla behaviour goes in a bundled `<script>` (TypeScript, `import` from npm). React islands
  (`client:load` / `client:visible`) only when the skill is React-based or genuinely needs it.
- The **first viewport is the card preview** (captured at 1440×900 after ~3.5 s): it must show the
  skill's effect/system at its best, not a blank intro or a loader.
- Responsive 390 → 1440 with no horizontal overflow; honour `prefers-reduced-motion`;
  no console errors; keyboard-accessible controls.
- Original concept and copy — a fictional brand/product/story that suits the skill. The skill's
  `demo/preview.jpg` sets the quality bar; do not copy the demo.
- Images: own assets in `public/skills/<name>/`, files from the skill's `demo/assets/` copied
  there, or `https://images.unsplash.com/...` URLs.

`src/data/meta/<name>.json`:

```json
{
  "title": "Marquee Loop",
  "kind": "section",
  "category": "Effects & details",
  "concept": "One sentence: what the example page is.",
  "notes": "Optional: limitations, CDN deps, WebGPU fallbacks."
}
```

`kind`: `website` (a full multi-section page) or `section` (one focused section/effect).
`category`: one of `Design systems`, `Layout`, `Motion & scroll`, `3D & WebGL`,
`Backgrounds & atmosphere`, `Effects & details`, `Components`, `Page types`.
